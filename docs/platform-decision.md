# Platform Decision: Web or iOS

## Current Position

Do not decide the final developer direction yet.

Start by designing the budget builder as a product experience. The strongest bachelor project will come from clearly explaining the customer problem, the flow, the forecast logic, and the design choices before committing too heavily to one technical platform.

## Web Prototype

Best if the first goal is to move quickly.

Strengths:

- Fast to build and change.
- Easy to share with supervisors, classmates, and test users.
- Good for testing layout, wording, and flow.
- Lower setup friction.

Tradeoff:

- Less representative of the real Danske Bank mobile app environment.

## iOS Prototype

Best if the project should demonstrate native mobile craft.

Strengths:

- Closer to how a banking app feature would actually feel.
- Strong fit for SwiftUI, gestures, sheets, and native navigation.
- Useful if the career question leans toward iOS development.

Tradeoff:

- Slower iteration and more platform-specific decisions earlier in the project.

## Recommended Path

1. Start with a platform-neutral product structure and brief.
2. Build a small web prototype first to validate the budget flow.
3. Recreate one or two key screens in SwiftUI if iOS still feels interesting.
4. Use the comparison as part of the bachelor project reflection.

This keeps the project practical while still helping answer the career question.
